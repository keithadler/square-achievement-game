Subject: n = 6 through 14 resolved: the first player wins for every n >= 5

I ran an exhaustive forced-win search on the nine board sizes that were still
open, and all nine are first-player wins, in every case forced within 13 plies:

n=6: 36 cells, 55 squares -- first player wins, 13 plies, 2,016,166 nodes
n=7: 49 cells, 91 squares -- first player wins, 13 plies, 2,644,635 nodes
n=8: 64 cells, 140 squares -- first player wins, 13 plies, 5,682,421 nodes
n=9: 81 cells, 204 squares -- first player wins, 13 plies, 21,674,452 nodes
n=10: 100 cells, 285 squares -- first player wins, 13 plies, 56,785,588 nodes
n=11: 121 cells, 385 squares -- first player wins, 13 plies, 116,660,038 nodes
n=12: 144 cells, 506 squares -- first player wins, 13 plies, 231,698,908 nodes
n=13: 169 cells, 650 squares -- first player wins, 13 plies, 735,265,715 nodes
n=14: 196 cells, 819 squares -- first player wins, 13 plies, 746,507,072 nodes

Together with Jenrich's n = 3, 4 (draw) and n = 5 (first-player win), and with
Bacher-Eliahou plus strategy stealing giving the first player the win from
n = 15 on, this settles the problem as stated: the game is a draw for n <= 4
and a first-player win for every n >= 5.

Method. A full solve of even the 36-cell board is out of reach, but it is not
needed. Run negamax with the search horizon scored as a draw. Then the value +1
can only be returned when the side to move actually completes a square inside
the horizon, so a depth-limited search reporting a win has proved a win. (Only
a reported draw would be inconclusive, and no case here needed one.) Searching
directly at depth 13 avoids the expensive depth-11 refutations entirely.

Three sound rules do most of the pruning. If some empty cell completes a square
for the side to move, return a win. Otherwise, if the opponent has two distinct
cells that each complete a square for them, the position is lost, since only one
can be blocked. If exactly one such cell exists, it is the only non-losing move,
so branching collapses to one. On top of that: bitboards, a transposition table,
folding by the eight symmetries of the square, and move ordering favouring cells
in already half-owned squares.

Certificate for n = 6. A separate pass walked the whole strategy tree - every
first-player move and every legal reply at every node - and confirmed that each
of its 54,480,689 leaves is a genuinely completed square owned by the first
player, over 56,857,431 decision nodes, aborting if the second player could ever
complete a square first. The first player opens at c4; one line runs
1. c4 a6  2. c6 b6  3. b5 d6  4. e6 f6  5. e4, closing c4-e4-c6-e6.
13 plies is the worst case over all defences, not the length of this line.

Checks. The solver reproduces all three published values, including that the
n = 5 win first appears at depth 17 and not earlier. A second, separately
written implementation agrees on n = 6, 7, 8. A third, deliberately naive one -
array board, no transposition table, no symmetry folding, no move ordering -
confirms the n = 4 draw over 63.5M nodes. Re-running n = 6, 7, 8 with symmetry
folding disabled gives the same answers at higher node counts.

Incidentally, a pairing strategy for the second player is impossible from n = 5
on, by counting: two cells lie together in at most two squares, so 18 pairs
cover at most 36 of the 55 squares on a 6x6 board. The same count permits n = 4
and rules out n = 5, which is exactly where the draws stop.

The C sources and run logs are available on request. These results are
machine-checked but have not been refereed, and I would welcome independent
confirmation.
